## Purpose and authority boundary

BESS QA/QC Toolkit organizes project-neutral records for FAT, SAT, commissioning, closeout and handover. Its Python checks evaluate documented fields and relationships. The browser lesson explains fictional review capacity. Neither the repository maintainer nor a passing command acquires project energization, regulatory, contractual, or engineering approval authority through the software. ## Project adaptation procedure

1. Copy templates into an appropriately controlled project record system; record their source revision.
2. Assign actual project owners and required review authorities outside the software.
3. Define project-specific status, completeness, evidence, calibration, punch, handover and revision-control requirements. Review example policy vocabulary rather than assuming it is universally suitable.
4. Select an explicit input manifest and applicable command set. The readiness command alone does not include every specialized check.
5. Preserve the assessment date, policy versions, outputs, evidence references and independent approvals.
6. Resolve findings through the project process. Do not change a date, classification, placeholder or allowlist merely to obtain a pass.
7. Keep actual acceptance and energization decisions in the authorized project governance record.
