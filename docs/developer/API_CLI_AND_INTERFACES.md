# API, CLI and interfaces

[Handbook index](../INDEX.md)

## Interface contract

The primary interfaces are ten Python command-line scripts, local Markdown records, three example JSON policies and Markdown/JSON reports. The modules also expose importable functions and frozen dataclasses, listed below. These are source-defined interfaces; the repository does not declare a packaged SDK or a semantic-version compatibility promise. Browser globals are a separate teaching interface. [scripts/audit_readiness.py](https://github.com/mohammadrezwankhan/bess-qaqc-toolkit/blob/af44c932684dfd120dea05d150cefcc3e47539a0/scripts/audit_readiness.py#L1-L65) [docs/index.html](https://github.com/mohammadrezwankhan/bess-qaqc-toolkit/blob/af44c932684dfd120dea05d150cefcc3e47539a0/docs/index.html#L150-L154) [docs/index.html](https://github.com/mohammadrezwankhan/bess-qaqc-toolkit/blob/af44c932684dfd120dea05d150cefcc3e47539a0/docs/index.html#L335-L335)

## Command selection

All commands below are prefixed with `python scripts/`. Every parser provides `-h/--help`. Unless stated otherwise, positional `paths` accepts zero or more paths, `--format` is `markdown` or `json` (default `markdown`), and `--output PATH` writes the report.

| Script | Default input / required options | Additional options |
| --- | --- | --- |
| `validate_templates.py` | All `templates/*.md`; explicit inputs are files, not directory expansion | `--strict-governance`; no JSON/output mode |
| `summarize_status.py` | `templates` | `--policy PATH`, repeatable `--fail-on STATUS` |
| `audit_deadlines.py` | `templates`; required `--as-of YYYY-MM-DD` | Repeatable `--date-column`, `--terminal-status`, `--missing-date-value`, `--fail-on STATE` |
| `audit_completeness.py` | `templates`; required `--policy PATH` | Common format/output options |
| `audit_readiness.py` | `templates`; required `--status-policy`, `--completeness-policy`, `--as-of` | `--require-source-coverage`, repeatable `--deadline-fail-on`, `--date-column`, `--terminal-status`, `--missing-date-value` |
| `audit_evidence_traceability.py` | `examples/commissioning-evidence-traceability-passing.md` | Repeatable `--completed-status`, `--accepted-evidence-status`, `--missing-value` |
| `audit_calibration_traceability.py` | `examples/calibration-traceability-passing.md` | Optional `--as-of`; repeatable `--completed-status`, `--accepted-calibration-status`, `--missing-value` |

## Record and policy schemas

Recognized headings are normalized case-insensitively with collapsed whitespace. Multiple aliases matching the same required field are generally rejected where the extractor needs one unambiguous column. Completeness required-field aliases are alternatives: at least one present, nonmissing alias value satisfies a field. [scripts/summarize_status.py](https://github.com/mohammadrezwankhan/bess-qaqc-toolkit/blob/af44c932684dfd120dea05d150cefcc3e47539a0/scripts/summarize_status.py#L56-L69) [scripts/audit_completeness.py](https://github.com/mohammadrezwankhan/bess-qaqc-toolkit/blob/af44c932684dfd120dea05d150cefcc3e47539a0/scripts/audit_completeness.py#L244-L326)

| Policy | Shape | Important semantics |
| --- | --- | --- |
| Status | `allowed_statuses`, `blocking_statuses`, Boolean `require_status`, optional `column_rules` | A matched column rule supplies a complete replacement rule; unknown fields and duplicate normalized values are rejected |
| Completeness | `missing_values`, nonempty `rules`; each rule has `name`, `match.columns`, `match.values`, `required_fields[].label/columns` | Only matching rows are evaluated; unmatched rows are not proof of completeness |
| Handover | Explicit status/severity/decision classifications and missing values | Punch classifications partition all allowed states; risk status sets are disjoint; conditional decisions are release decisions |

Sources: [scripts/summarize_status.py](https://github.com/mohammadrezwankhan/bess-qaqc-toolkit/blob/af44c932684dfd120dea05d150cefcc3e47539a0/scripts/summarize_status.py#L207-L276), [scripts/audit_completeness.py](https://github.com/mohammadrezwankhan/bess-qaqc-toolkit/blob/af44c932684dfd120dea05d150cefcc3e47539a0/scripts/audit_completeness.py#L89-L201), [scripts/audit_handover_acceptance.py](https://github.com/mohammadrezwankhan/bess-qaqc-toolkit/blob/af44c932684dfd120dea05d150cefcc3e47539a0/scripts/audit_handover_acceptance.py#L132-L206).

Example policies are project-neutral examples, not one universal vocabulary. For instance the supplier tracker documents `Revise and resubmit`, `Approved with comments` and `Superseded`, while the example `Review Status` rule permits only four named states. Establish a controlled policy deliberately. [templates/supplier-document-review-tracker.md](https://github.com/mohammadrezwankhan/bess-qaqc-toolkit/blob/af44c932684dfd120dea05d150cefcc3e47539a0/templates/supplier-document-review-tracker.md#L13-L20) [config/readiness-status-policy.example.json](https://github.com/mohammadrezwankhan/bess-qaqc-toolkit/blob/af44c932684dfd120dea05d150cefcc3e47539a0/config/readiness-status-policy.example.json#L25-L35)

Reports retain source paths and line numbers. Their dictionaries are constructed by the public `summarize_*`/`evaluate_readiness` functions below; there is no separate versioned JSON-report schema. Consumers should pin a revision and test the fields they depend on.

## Browser interface

The explicit global `window.LabSimulation` (also CommonJS-exportable) exposes `MODEL_SPECS`, `getModelSpec`, `resolveParameters`, `evaluateModel` and `checkCheckpoint`. The selected UI model is `security`; parameters represent synthetic findings and reviewers. `resolveParameters` clamps finite numeric inputs to the built-in ranges, substitutes built-in defaults otherwise, and does not snap values to the UI slider step. `evaluateModel` clamps time to the model horizon. [docs/index.html](https://github.com/mohammadrezwankhan/bess-qaqc-toolkit/blob/af44c932684dfd120dea05d150cefcc3e47539a0/docs/index.html#L150-L158) [docs/index.html](https://github.com/mohammadrezwankhan/bess-qaqc-toolkit/blob/af44c932684dfd120dea05d150cefcc3e47539a0/docs/index.html#L231-L246) [docs/index.html](https://github.com/mohammadrezwankhan/bess-qaqc-toolkit/blob/af44c932684dfd120dea05d150cefcc3e47539a0/docs/index.html#L335-L335)

The JSON file and embedded configuration hold lesson labels, defaults, presets, checkpoint tolerances and source provenance. The native catalog and portfolio guide are reading/navigation surfaces; neither executes Python. The guide uses local storage for study state, not controlled engineering records. [docs/lesson-config.json](https://github.com/mohammadrezwankhan/bess-qaqc-toolkit/blob/af44c932684dfd120dea05d150cefcc3e47539a0/docs/lesson-config.json#L54-L144) [docs/portfolio/index.html](https://github.com/mohammadrezwankhan/bess-qaqc-toolkit/blob/af44c932684dfd120dea05d150cefcc3e47539a0/docs/portfolio/index.html#L285-L307)
