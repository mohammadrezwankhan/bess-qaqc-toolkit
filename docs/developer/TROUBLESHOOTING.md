## Start with the process result

Most audit CLIs return 0 for no configured findings, 1 for input/configuration/extraction failure, and 2 for audit findings. `argparse` also returns 2 for invalid CLI usage, so read stderr before treating every 2 as a completed audit. The template validator uses 1 for validation failure. ## Avoid false fixes

Do not remove blocking statuses, alter date controls, fabricate a verifier, or replace an evidence reference merely to get exit 0. Resolve the documented gap in the controlled source, then rerun the relevant audit families. If a script lacks a required control, record the limitation and obtain the appropriate review rather than describing the output as proof.

In particular, source coverage can omit an entirely unrecognized input; handover approval dates are checked for presence without ISO date parsing; and the handover audit does not execute the Critical closeout verifier rule from the punch-list audit. These are recorded in [failure modes](../maintainer/FAILURE_MODES_AND_TECH_DEBT.md), with proposals in the [roadmap](../../ROADMAP.md). ## A useful defect report

Provide the immutable revision, Python version, exact command and working directory, sanitized minimal Markdown/JSON input, expected result, actual exit code, stdout and stderr. Keep genuine site records, personal signatures, credentials and confidential supplier material out of a public issue. Use [SECURITY.md](../../SECURITY.md) for sensitive reports and the existing [template-gap issue form](../../.github/ISSUE_TEMPLATE/template-gap.md) for safe public documentation gaps.
